# PRISM Code Intel: execution-verified code retrieval (Samsung PRISM GenAI Hackathon, Theme 01)

Retrieve the Python solution for a programming problem statement (MTEB `AppsRetrieval`), and search code
across versions of a codebase (P1 `--rev`, Bonus `--range`). Runs on CPU; a GPU only speeds up
development encodes.

> Numbers below are copied from files under `results/`, produced by scripts in this repo. Every run is
> logged in `docs/LOG.md` with command, config, commit and hardware. `[pending]` marks results of runs
> still in progress when this draft was written.

## 1. Approach

```
Stage 1 (recall)                                   Stage 2 (precision)
statement ──► Qwen3-Embedding-0.6B ──► cosine ──► top-k ──► parse sample I/O from the statement
solution  ──► Qwen3-Embedding-0.6B ──┘                      run each candidate in a Windows sandbox
             (text-keyed embedding cache)                   PASS / WRONG / ERROR / TIMEOUT / UNKNOWN
                                                            score = cos + 0.3·PASS − 0.05·WRONG − 0.05·ERROR
```

- **Stage 1**: `Qwen/Qwen3-Embedding-0.6B` with the query instruction "Given a programming problem
  statement, retrieve the Python solution that solves it" (`configs/stage1_final.yaml`).
- **Stage 2**: an execution check. Each top-k candidate program runs on the statement's sample input and
  its output is compared with the sample output (token-wise, numeric tolerance 1e-6). Candidates that
  pass move up. Uses only query text and document text (no IDs, no metadata, no labels).
  Two refinements: WRONG is not penalised when the statement accepts any valid answer, and PASS counts
  for 10% when every sample output is a single trivial token (0/1/YES/NO), where chance passes are common.
  Frozen in `configs/stage2_final.yaml` (k=20) and `configs/stage2_final_k50.yaml` (k=50, final).
- **Output A** (encoder only, guideline template) and **Output B** (MTEB two-stage: Output A's
  predictions re-ranked by `ExecutionReranker`, a cross-encoder in MTEB's protocol). Both JSONs are
  generated by `mteb.evaluate`.

## 3. Setup (clean Windows 11 machine)
Requirements: Windows 10/11 x64, 16 GB RAM, Python 3.11, git. No GPU needed.
```powershell
winget install Python.Python.3.11
git clone <repo-url> prism-code-intel; cd prism-code-intel
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python -m pip install -e .[dev]
# sandbox interpreter (python.org embeddable 3.11.9, signature-checked) + prints the firewall command
powershell -ExecutionPolicy Bypass -File scripts\setup_sandbox.ps1
# run the printed New-NetFirewallRule command ONCE in an administrator PowerShell
.venv\Scripts\python -m pytest -q        # includes 33 hostile-program sandbox tests
```
Set `PYTHONUTF8=1`. Long jobs: `.venv\Scripts\python scripts\bg.py logs\x.log -- <command>` (detached, no windows).

## 4. Reproduce the screening JSONs
From the embedding cache (fast, CPU):
```powershell
.venv\Scripts\python scripts\encode.py --config configs\stage1_final.yaml --device cpu   # ~1 h 50 min on CPU if no cache
.venv\Scripts\python -m codeintel.eval.run_two_stage --split test                         # Output A + Output B (k=20)
.venv\Scripts\python -m codeintel.eval.run_two_stage --split test --reuse-a --stage2-config configs\stage2_final_k50.yaml --out-suffix _k50
```
CPU runtimes on the dev machine (Ryzen 9 270, 8 cores): Stage 1 test run from cache ~25 s; full corpus +
test query encode ~1 h 50 min; Stage 2 at about 3-4 program executions/s (process start-up dominates
on this machine), so k=20 takes about 7 h and ranks 21-50 about 7-10 h more. Execution results are cached
(`cache/exec/`), so reruns are fast.

## 5. Versioned retrieval (P1 and Bonus)
```powershell
# index git revisions (incremental: unchanged content is never re-embedded; renames keep identity)
.venv\Scripts\python -m codeintel.versioned.cli index --store stores\demo --git C:\path\repo --revs v1 v2 v3
.venv\Scripts\python -m codeintel.versioned.cli index --store stores\snap --snapshots snaps\v1 snaps\v2
.venv\Scripts\python -m codeintel.versioned.cli index --store stores\js --jsonl v1.jsonl v2.jsonl
# P1: search one version
.venv\Scripts\python -m codeintel.versioned.cli search --store stores\demo --rev v2 "problem statement or query"
# Bonus: search all versions in a range, one result per unit with its history
.venv\Scripts\python -m codeintel.versioned.cli search --store stores\demo --range v1..v3 "query"
# --verify: execution re-rank when the query contains sample input/output
```
Store: `index.sqlite` (versions, units, revisions with [v_from, v_to], embeddings, snippets) plus
`vectors.npy`. Files over 300 lines are split into 80-line windows (20 overlap) and collapsed back to
files in results. P1/Bonus metrics (incremental vs full rebuild time, embeddings reused, CPU latency): [pending].

## 6. Sandbox security model (native Windows)
APPS solutions are untrusted code. They never run in the main process or with the project's Python.
Layers: (1) a dedicated python.org embeddable interpreter in `tools/sandbox-python/`, standard library
only; (2) a Windows Firewall rule blocking all its outbound traffic; (3) an audit-hook guard in
`src/codeintel/stage2/runner.py` that blocks process creation, sockets, ctypes/_winapi, registry,
deletes/renames and writes outside a per-run temporary directory; (4) a Job Object per run: 512 MB
memory, one process, CPU-time limit, kill on close, no error dialogs; (5) 2 s wall limit after start-up,
1 MB output cap, fresh working directory deleted afterwards, minimal environment, no console window.
**Limits**: this is user-space isolation on Windows Home (no Hyper-V, no containers). It is weaker than
a container or VM; Python audit hooks are not a security boundary. It is proportionate for public
competitive-programming solutions, not for malware. `tests/test_sandbox.py` exercises each layer.

## 7. Known limitations
- Stage 2 needs sample I/O in the statement (97.9% of test statements have it). Problems with several
  valid answers cannot be verified from one sample output; their gold solutions get no boost.
- Function-style problems (LeetCode/Codewars, 60% of APPS train but <1% of test) are not executed yet.
- Python 2 solutions and solutions importing non-standard modules are left neutral (UNKNOWN).
- Throughput on this machine is bound by Windows process start-up (~0.56 s per python.exe launch).
- Validation comes from APPS train, whose source mix differs from test (Section 2).
